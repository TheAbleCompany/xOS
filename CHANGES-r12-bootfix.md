# CHANGES: r12-bootfix -- загрузка на произвольных ПК (не только ASUS P553M)

## Симптом

ОС успешно загружалась только на ASUS P553M.  На любых других ПК
(QEMU с другим железом, ноутбуки/системники с SATA в режиме AHCI,
машины только с NVMe) загрузка замирала: на экране оставалось
консольное окно отладки (flanterm-консоль с двумя строками
"ArtyomXOS PIC keyboard test / kernel build: ...") и больше ничего
не происходило.  GUI (wserver) не запускался.

## Корневая причина

`drivers/disk.c` (legacy ATA PIO драйвер, канал 0x1F0, master):

```c
void ata_wait_bsy(void)
{
    while (inb(ATA_STATUS) & ATA_SR_BSY);   // <-- ВЕЧНЫЙ ЦИКЛ
}
```

`kernel/main.c` вызывает `hd_initialize()` ещё до инициализации PIC.
Последовательность IDENTIFY завершалась в `ata_wait_bsy()`, и если
legacy-IDE канала на машине нет (SATA в AHCI-режиме без
Compatibility Mode, чистые NVMe-системы, новые чипсеты), чтение
порта 0x1F7 возвращает 0xFF ("floating bus").  0xFF & 0x80 (BSY) --
и драйвер крутился в этом цикле вечно.  Ядро замирало на этапе
"Initializing ATA disk".

На ASUS P553M SATA-контроллер работал в legacy/IDE-режиме и диск
реально отвечал на 0x1F0 -- поэтому там проблема не проявлялась.

Дополнительные проблемы того же класса:

1. `ata_wait_drq()` -- второй вечный цикл (при статусе без ERR и
   без DRQ, например 0x50 навсегда после сбояной команды).
2. После IDENTIFY диск мог поднять IRQ14 ещё ДО ремапа PIC.  BIOS
   маппит IRQ14 на вектор 0x0E -- это Page Fault в IDT ядра:
   случайные тройные фолты на части машин.
3. `kernel/main.c`: при `mods_count == 0` (нет модуля initrd) ядро
   разыменовывало нулевой `mods_addr` -- мгновенный краш.
4. `server/wserver_ui.c`: батарея читалась из EC-регистра 0xB0
   (специфика ноутбуков ASUS) на каждой перерисовке меню-бара; на
   машинах без EC порты 0x62/0x66 дёргались впустую постоянно.
5. `drivers/mouse.c` `mouse_debug()` -- вывод в flanterm всегда
   нулевой длины (указатель уже за концом строки) + нет проверки
   ft_ctx.
6. `drivers/timer.c` `sleep()` -- сравнение константы с константой
   (`while (timer_ticks < end)`), вечный цикл при любом вызове.

## Фиксы

### 1. drivers/disk.c -- полностью переносимый ATA-стек

- `ata_wait_bsy()` / `ata_wait_drq()` -- ограничены таймаутом
  (5 000 000 итераций, на реальном железе это секунды запаса;
  успех-путь занимает микросекунды).  Вечных циклов больше нет.
- Детекция "мёртвой" шины: статус 0xFF (floating bus, AHCI/NVMe
  системы) или 0x00 (нет устройства) -- немедленный выход.
- `hd_initialize()`:
  - выбор master + `outb(0x3F6, 0x02)` (nIEN=1): прерывания канала
    отключены на всё время работы polling-драйвера -- IRQ14 больше
    не может прилететь на вектор 0x0E до ремапа PIC;
  - распознавание не-ATA устройств по сигнатуре LBA_MID/LBA_HIGH:
    ATAPI (0x14/0xEB), SATA (0x3C/0xC3), SATAPI (0x69/0x96) --
    аккуратно пропускаются с сообщением;
  - глобальный флаг `ata_drive_present()`.
- `hd_read_sector()` / `hd_write_sector()` теперь возвращают
  `int` (1 = успех, 0 = ошибка/нет диска) и никогда не зависают.
- При отсутствии диска ядро ПРОДОЛЖАЕТ загрузку: disk0 просто не
  монтируется (initrd и GUI работают как обычно).

### 2. fs/ix/ixk_storage.c

`ixk_storage_read()` проверяет `ata_drive_present()` и пробрасывает
результат каждого секторного чтения.  `diskfat_init()` на машине
без legacy-ATA теперь мгновенно возвращает "не смонтировано".

### 3. kernel/main.c

- Защита initrd: initrd читается только при `mods_count > 0`
  (раньше -- разыменование нулевого указателя).
- Новая функция `boot_stage()`: этап загрузки печатается И в COM1,
  И на экранный консоль.  Теперь на любой машине видно, где именно
  ядро находится ("stage: ATA disk probe", "stage: PS/2 init",
  "stage: launching wserver (GUI)..."), -- консоль отладки больше
  не выглядит "зависшей" молча.

### 4. server/wserver_ui.c -- переносимая батарея

- EC опрашивается ОДИН раз; если регистр 0xB0 не возвращает
  процент (0..100) -- порты 0x62/0x66 больше не трогаются никогда.
- На ASUS значение кэшируется и обновляется раз в 4096 обращений
  (~минута при 60 fps), а не на каждом кадре.

### 5. Мелочи

- `drivers/mouse.c`: `mouse_debug()` пишет в flanterm правильный
  указатель/длину и проверяет ft_ctx.
- `drivers/timer.c`: `sleep()` сравнивает глобальный `tick`.
- `Makefile`: на Linux автоматически используется
  `limine-binary/limine-tool` (собран и добавлен в репозиторий),
  на Windows -- прежний `limine.exe`.

## Проверка

1. Хост-тест `scripts/test_disk_ata.c` (эмуляция портов ATA):
   - floating bus 0xFF (воспроизведение зависания) -> выход без
     зависания, present=0;
   - нет устройства 0x00 -> чистый пропуск;
   - реальный диск -> IDENTIFY + чтение сектора работают.
   Сборка/запуск:
   ```
   gcc -O2 -c drivers/disk.c -o /tmp/disk.o
   gcc -O2 -I. scripts/test_disk_ata.c /tmp/disk.o -o /tmp/ata_test
   /tmp/ata_test    # RESULT: ALL PASSED (no hangs)
   ```

2. Пересобраны и заменены артефакты: `main.elf` (ядро),
   `server/wserver.bin` (+ новый `initrd.img`), собран новый
   `main.iso` (Limine 12.3.3, BIOS+UEFI, гибридный).

3. Рекомендуемая проверка на другой машине:
   ```
   qemu-system-x86_64 -cdrom main.iso -m 512M -serial stdio
   ```
   На экране должны смениться все "stage: ..." строки, включая
   "stage: disk0 absent (no ATA/FAT) -- continuing" на машинах без
   legacy-IDE, и затем запуститься GUI.  По COM1 -- полный лог.

## Ожидаемое поведение на разных ПК

| Железо                              | Результат загрузки                       |
|-------------------------------------|------------------------------------------|
| ASUS P553M (IDE-режим)              | как раньше, disk0 монтируется            |
| SATA в AHCI, есть legacy-порты      | диск детектируется, disk0 монтируется    |
| SATA в AHCI без legacy-портов       | "no legacy IDE channel", загрузка идёт дальше, GUI работает с initrd |
| Только NVMe                         | как в предыдущем случае                  |
| Нет PS/2 мыши                       | "[MOUSE] initialization failed", GUI работает только с клавиатурой |
| Нет EC (десктоп)                    | индикатор батареи показывает 0, EC не опрашивается |
