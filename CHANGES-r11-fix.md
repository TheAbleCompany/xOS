# CHANGES: r11-регрессия сисколл-стаба («содержимое окон не рендерится»)

## Симптом

После v2-фикса #GP(0x500) wserver стартует нормально, но:

- окна приложений открываются: titlebar, трафик-светофор, меню-бар приложения;
- внутри окна -- только начальная заливка канваса `ARGB(0xF0, 28, 28, 34)`;
  ничего из того, что клиент нарисовал (текст, кнопки, иконки), не появляется;
- окна `files`, `cube` (GL Demo), `temu` (XSH), `notes` -- все одинаково пустые.

## Диагностика

Трассировка портов в ядре и в wserver показала:

1. `MSG_REQ_SURFACE` доходит до сервера, канвас выделяется, `REPLY_SURFACE`
   уходит (`rc=0`) -- и доставляется клиенту.
2. Клиент **успешно пишет в канвас** (SHM через общий HHDM: запись и readback
   совпадают, например `px0=0xFFFFFFFF` после отрисовки).
3. Клиент отправляет `MSG_REQ_COMMIT` -- ядро подтверждает постановку в очередь
   порта wserver (`IPC SEND->srv type=3`).
4. **Сервер сообщение не забирает**: `port_recv` на порт 1 больше не возвращает
   сообщений, главный цикл wserver замирает; клиент зацикливается.

Ключевой эксперимент -- round-trip тест на клиенте:

```
movq $0xDEADBEEFCAFE1234, %r11
int $0x80            # yield (151)
movq %r11, %rax      # <- в v2 приходил СТАРЫЙ RSP, а не магия
```

## Причина

Регрессия v2-фикса. Новый `SYSCALL_STUB` (векторы 128/129/130) начинался так:

```asm
mov r11, [rel ax_cur_kstack]   ; пользовательский r11 УЖЕ УНИЧТОЖЕН
xchg rsp, r11                  ; r11 = старый пользовательский RSP
push qword [r11+40]            ; кадр строится на ядерно-стеке
...
```

После `iretq` пользователь получал `r11 = свой старый RSP`. Наши бинарники
(GCC `-O2` и TCC) используют inline-asm `int $0x80` **без** `"r11"` в списке
clobber'ов (в отличие от инструкции `syscall` в Linux, где r11/rcx губятся
документированно), поэтому компилятор свободно держит в r11 живые переменные.
Каждый сисколл молча портил их: у клиентов рассыпались циклы
`ax_wait_reply`/`ax_poll` и рендер -- приложение не доходило до
`render()+ax_commit()`, сервер никогда не получал COMMIT.

До v2 этой проблемы не было: кадр int 0x80 строился прямо на стеке задачи и
r11 не использовался (зато был #GP(0x500) из-за red zone -- см.
CHANGES-windowserver-fix.md).

## Фикс

### 1. kernel/asm/interrupt.asm

Пользовательский r11 сохраняется в глобальный слот **до** переключения стека:

```asm
global ax_user_r11_save
ax_user_r11_save: dq 0

%macro SYSCALL_STUB 1
  isr%1:
    cli
    mov [rel ax_user_r11_save], r11   ; сохранить r11 ПОЛЬЗОВАТЕЛЯ
    mov r11, [rel ax_cur_kstack]
    xchg rsp, r11
    push qword [r11+40]               ; pad
    push qword [r11+32]               ; SS
    ...
%endmacro
```

Запись `mov [rel slot], r11` не портит ни один регистр, кроме самого r11
(значение которого мы и сохраняем), и не пишет на пользовательский стек
(red zone остаётся нетронутой -- инвариант v2 сохранён).

### 2. lib/syscalls.c (вектор 128) и kernel/compat.c (129/130)

В начале каждого из трёх C-обработчиков:

```c
extern u64int ax_user_r11_save;
regs->r11 = ax_user_r11_save;   /* регистровый слот кадра */
```

`isr_common_stub` в эпилоге делает `pop r11` из этого слота -- пользователь
получает свой исходный r11 одновременно с `iretq`. Одноядерность +
`cli` в стабе гарантируют атомарность слота.

### 3. apps/guitest.c -- smoke-тест IPC (новый, в initrd)

Мини-клиент, который проходит весь путь `ax_surface -> рисование ->
ax_commit -> ax_poll` и печатает каждый шаг в COM1. Запуск из терминала:
`exec guitest`. На рабочий стол выводит красное поле с белой рамкой.

## Проверено в QEMU (qemu 10.0.13, -M pc -m 512M, cdrom + testdisk)

- boot: 0 исключений, `WSERVER START -> SCR:1280x800 -> port id=1`;
- `Files`: заголовок "Files - initrd filesystem", сайдбар (initrd/disk0),
  сетка иконок (dev, initrd, disk0, wserver, temu, notes, prefs, files,
  guitest), скроллбар, статус "OK";
- `Calculator`: кнопки 7-9/4-6/1-3/0-C-=-+, дисплей "0";
- `Notes`: поле редактора с курсором, статус-бар "Ctrl+S Save ...";
- меню-бар переключается на сфокусированное приложение (macOS model);
- перекрытие окон и z-order корректны (Files за Calculator'ом);
- r11 round-trip: `0xDEADBEEFCAFE1234 == 0xDEADBEEFCAFE1234 [OK]`.
