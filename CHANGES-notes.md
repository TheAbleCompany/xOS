# Обновление: сохранение в Notes через Ctrl+S и открытие файлов

## Что сделано

### 1. Ctrl+S теперь реально работает (драйвер клавиатуры)
Раньше `axshell.c` ждал сканкод 0xF1 (Ctrl+S), но драйвер клавиатуры
вообще не отслеживал Ctrl — нажатие просто печатало букву "s".
Теперь драйвер (`drivers/keyboard.c`):
- отслеживает зажатый Ctrl (сканкоды 0x1D / 0x9D);
- при Ctrl+S, Ctrl+O, Ctrl+N отправляет в GUI специальные коды
  (0xF1 / 0xF4 / 0xF5) вместо обычной буквы;
- остальные Ctrl+комбинации не печатают буквы в документ.

### 2. Комбинации клавиш проброшены в приложения
- `lib/axipc.h` — убран конфликтующий дубль `AX_KEY_CTRL_S`
  (был объявлен дважды с разными значениями!), добавлены
  `AX_KEY_CTRL_O` и `AX_KEY_CTRL_N`.
- `kernel/axshell.c` — новые коды 0xF4/0xF5 маппятся в события
  `AX_KEY_CTRL_O` / `AX_KEY_CTRL_N` для активного окна.

### 3. Notes — полноценный редактор (`apps/notes.c`, переписан)
- **Ctrl+S** — сохранить текущий файл (O_WRONLY|O_CREAT|O_TRUNC).
- **Ctrl+O** — открыть файл: внизу появляется строка «Open: …»,
  вводите имя, Enter — загрузить, Esc — отмена.
- **Ctrl+N** — новый документ (untitled.txt).
- Имя файла берётся из argv[1] (запуск `notes test.txt` из
  терминала или из Files). Аргументы читаются через exec_args_t,
  который ядро кладёт в RDI при старте задачи.
- Статус-бар: имя файла, маркер изменений (*), сообщения
  «Saved: …», «Opened: …», «Not found: …» и подсказка клавиш.
- Автопрокрутка к курсору, корректная обработка Backspace/Enter/Tab,
  защита от управляющих символов и выхода за границы шрифта (ASCII).

### 4. Files открывает текстовые файлы (`apps/files.c`)
- Первый выбор файла — выделение, второй — открытие (как раньше).
- Если файл начинается с ELF-магии (0x7F 'E' 'L' 'F') — запускается
  как программа (прежнее поведение).
- Иначе — открывается в Notes с именем файла в аргументе
  (аналог `notes test.txt`).

### 5. Исправлена порча кучи при сохранении (критический баг!)
`open()` с O_TRUNC в `lib/syscalls.c` делал
`memset(fsnode->ptr, 0, 65536)`, хотя для файлов, созданных во время
работы, `ptr` — это маленькая структура `initrd_ram_file_t` (24 байта).
Итог — затирание 64КБ памяти ядра при ВТОРОМ сохранении в тот же файл.
Теперь обрезка файла выполняет корректная функция
`initrd_truncate()` (добавлена в `fs/initrd.c/.h`), которая правильно
сбрасывает RAM-копию файла. Первое сохранение работало, второе —
могло уронить систему.

### 6. Добавлен syscall close (номер 6)
- `lib/syscalls.c` — реализация `close(fd)` + обработчик case 6.
- `lib/unistd.h` — пользовательская обёртка для приложений.
Без него каждое сохранение протекало: file_t не освобождался,
и после ~60 сохранений приложение оставалось без дескрипторов
(лимит задачи 64).

### 7. Терминал (temu) игнорирует спец-клавиши
Ctrl+S/O/N больше не вставляют в командную строку мусорный байт.

### 8. Сборка
- `apps/Makefile` — добавлено правило сборки `notes.bin`.

## Как пользоваться
- Открыть Notes → печатать → **Ctrl+S** (сохранится в untitled.txt
  или в имя, с которым Notes открыт).
- **Ctrl+O** → ввести имя (например `test.txt`) → **Enter**.
- В Files: два клика по `test.txt` — откроется в Notes.
- В терминале: `notes test.txt`.

## Пересборка артефактов
В архиве уже пересобраны: `main.elf`, `apps/initrd.img`,
`apps/notes.bin`, `apps/files.bin`, `apps/temu.bin`, `main.iso`.
Для самостоятельной сборки ISO (нужен xorriso + limine-утилита):
    make limine-iso
ISO в архиве собран без гибридного MBR (только El Torito BIOS+UEFI),
qemu `-cdrom` загружается нормально; для загрузки с USB на реальном
железе пересоберите ISO своей командой `make limine-iso`.
