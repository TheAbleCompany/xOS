# CHANGES -- WindowServer (userspace GUI) и Lion Edition

История изменений архитектуры GUI ArtyomX64.  Модель -- NeXTSTEP /
Mac OS X: GUI живёт в отдельном процессе-сервере (server/wserver*.c),
приложения-клиенты общаются с ним сообщениями через порт "wserver"
(lib/axport.h), канвасы -- разделяемая память (SHM_ALLOC).

## r14 -- "Lion Edition" (OS X 10.7): Launchpad / Mission Control / Fullscreen

Новые файлы:

    server/wserver_lion.c   -- Launchpad + Mission Control + кэш блюра
    tools/lion_harness.c    -- хост-харнесс: рендер кадров GUI на обычном
                               Linux без запуска ОС (скриншоты в BMP)

### 1. Launchpad (F4, иконка-ракета в доке, меню "X" -> Launchpad)

Полноэкранная сетка всех установленных приложений -- флагманская фича
OS X 10.7.  Построена на новых возможностях ОС:

  * список приложений синхронизирован с initrd (apps/Makefile);
  * запуск иконки = request_launch() -> exec() через ядро, тот же
    путь LaunchServices, что у дока;
  * фон оверлея -- СНИМОК текущего кадра, "дорогой" blur по-дешёвому:
    box-декеймация 1/6 -> апскейл gfx_blit_argb_scaled -> 2 прохода
    gfx_blur_region (эффект гаусса с радиусом в десятки px за O(S/36));
    кэш живёт в SHM-буфере, каждый кадр -- только blit + затемнение;
  * клик по пустому месту, Esc или повторное F4 закрывают сетку.

### 2. Mission Control (F3, меню "X" -> Mission Control)

Полноэкранный Exposé: все живые окна (включая свёрнутые) раскладываются
адаптивной сеткой (1-4 колонки).  Каждая карточка -- мягкая тень,
белая стеклянная панель, мини-тайтлбар с именем окна, aspect-fit
миниатюра канваса (gfx_blit_argb_scaled) и подпись процесса
(PROC_NAME-сисколл, как у дока).  Свёрнутые окна помечены жёлтой
точкой.  Клик по карточке: surf_focus + genie-восстановление
(AX_ANIM_RESTR) + закрытие оверлея.

### 3. Fullscreen -- зелёный светофор / F11 (как в настоящем Lion)

  * toggle_fullscreen() в wserver_surface.c: окно занимает ВЕСЬ экран,
    геометрия запоминается в fs_x/fs_y/fs_w/fs_h;
  * compose() прячет меню-бар, док и виджеты, пока есть видимое
    полноэкранное окно; курсор у верхнего края (<3px) возвращает
    меню-бар -- тот же механизм, что в OS X 10.7;
  * h_resize пропускает полноэкранному окну канвас во весь экран
    (scr_h - тайтлбар) вместо обычного клампа;
  * перетаскивание/ресайз полноэкранного окна запрещены;
  * приложение получает AX_EV_RESIZE и само пере-раскладывает канвас
    (ax_resize); старые приложения, не обрабатывающие resize,
    рисуются масштабированным blit'ом.

### 4. Системные клавиши Lion (работают БЕЗ фокуса окна)

    F3  -- Mission Control        (дефолт Lion)
    F4  -- Launchpad              (дефолт Lion)
    F11 -- fullscreen активного окна
    Esc -- закрыть оверлей

Перехват -- в process_input() ДО доставки в сфокусированное окно;
пока оверлей открыт, остальная клавиатура приложениям не доставляется.

### 5. Мышь

  * зелёная кнопка тайтлбара = fullscreen (Lion), а не maximize;
  * двойной клик по тайтлбару = zoom (toggle_maximize);
  * клики при открытом оверлее не проходят в окна/док/меню.

### 6. Док и меню

  * первой иконкой дока стала ракета Launchpad (процедурная Aqua-
    иконка, тогглится как оверлей);
  * меню "X": "Program Manager" (бинарника progman не существовало --
    мёртвая ссылка) заменён на "Mission Control" + "Launchpad";
  * диспетчер иконок lion_icon_tile()/lion_icon_art() в wserver_ui.c:
    док и Launchpad рисуют ОДНИ и те же плитки; добавлены иконки
    Raycaster, Bench, GUI Test, Launchpad;
  * метрики дока адаптивные: на экранах <= 860px иконки/отступы
    сжимаются, чтобы 10 иконок влезали.

### 7. Починен z-order рендера окон

compose() рисовал окна в ПОРЯДКЕ ЗАПИСИ в таблице, а не по z:
сфокусированное (и полноэкранное) окно могло оказаться ПОД более
старым.  Теперь рендер идёт по возрастанию z (стек окон).

### 8. Фикс ввода при масштабировании окон (bugfix)

Баг: "окна при масштабировании не реагируют на кнопки -- как внутри,
так и снаружи приложения (светофоры тоже)".  Три корня, все в
wserver_input.c:

  * клики в верхней полосе экрана (y < AX_MENUBAR_H = 24) ВСЕГДА
    уходили в меню-бар, даже когда он скрыт.  В fullscreen там стоит
    СОБСТВЕННЫЙ тайтлбар окна (28px) со светофорами -- поэтому
    красная/жёлтая/зелёная кнопки и drag тайтлбара были мертвы.
    Фикс: в fullscreen меню-бар принимает клики только в зоне
    reveal (курсор у самого верха, y < 3 -- ровно там он и
    рисуется, см. compose());

  * клики в нижней полосе уходили в СКРЫТЫЙ док (запускали
    приложения из fullscreen!), а по области скрытых виджетов -- в
    их drag.  Фикс: док/виджеты принимают клики только когда хром
    реально нарисован (нет активного fullscreen-окна);

  * координаты мыши в AX_EV_MOUSE шли в координатах ОКНА, а
    приложение хит-тестит свои кнопки в координатах КАНВАСА.  Пока
    канвас != клиентской области (приложение не пере-вызвало
    ax_resize после максимизации/fullscreen), контент рисуется
    масштабированным blit'ом -- и все кнопки ВНУТРИ приложения
    уходили мимо.  Фикс: ev_canvas_x/ev_canvas_y() масштабируют
    ev.mx/ev.my из window-space в canvas-space (те же пропорции,
    что у gfx_blit_argb_scaled); при канвасе == клиенту масштаб
    1:1, поведение старых приложений не меняется.

Регрессионные тесты -- инъекция кликов в tools/lion_harness.c
(5 сценариев: зелёная кнопка в/из fullscreen, жёлтая кнопка в
fullscreen, скрытый док не ест клики, тайтлбар fullscreen не
открывает меню, масштаб (512,400)->(215,160) в serial-логе).

### 9. Запуск консольных программ из файлового менеджера

console-ELF'ы, помеченные в mkinitrd2 ("console"), теперь открываются
в терминале: Files запускает temu, а temu выполняет программу в
своём pty -- вывод и ввод идут в окно терминала, по завершении
программы шелл возвращается к промпту.

Механика:

  * новый syscall 197 FP_TYPE (fs/exec.c: fp_type()) возвращает
    fs_node_t::program_type по пути: -1 / PROGRAM_NONE /
    PROGRAM_CONSOLE / PROGRAM_GUI.  Для initrd это метка app_type
    из заголовка mkinitrd2, для disk0/FAT -- PROGRAM_NONE;
  * files.c при загрузке каталога запрашивает тип каждого файла и:
      - рисует console-программы терминальной иконкой
        (aq_icon_terminal), остальные ELF'ы -- как раньше;
      - при открытии console-ELF'а делает
        exec("temu", 2, {"temu", path}) вместо прямого exec();
      - обычные (gui) ELF'ы и документы открываются по-прежнему;
  * temu принимает exec_args_t (argv[1] -- путь программы):
      - заголовок окна "XSH: <имя>", чтобы терминалы различались;
      - копирует путь в свой буфер и выполняет через run_cmd():
        программа наследует pty терминала (fs/exec.c: не-GUI
        ребёнок получает ctty вызывающего), вывод идёт в окно;
      - автозапуск происходит ПОСЛЕ первого кадра -- к этому
        моменту окно уже подключено к серверу и pty существует;
      - ПРАВКА: перед автозапуском обязателен ax_term_claim() --
        pty прикрепляется к окну ЛЕНИВО (при первом ax_term_read),
        а ctty выдаётся только в ipc_term_open(); без claim'а
        автозапуск идёт до первого drain_pty, ребёнок рождается
        без stdio и его вывод пропадает (симптом: в терминале
        видно только "$ initrd/ls" и больше ничего).

Валидация: scripts-инструмент читает initrd.img и сверяет app_type
каждой записи с планом (console: ls, rm, cat, echo, test, bench, run;
gui: wserver, temu, notes, prefs, files, guitest, calc, raycaster,
cube, doom, quake) + целостность оффсетов.

### 10. Прочее

  * quake.bin добавлен в initrd (apps/Makefile): иконка Quake в доке
    раньше запускала бинарник, которого в initrd не было;
  * host-harness: -DHOST_HARNESS теперь безопасно собирает ВЕСЬ
    сервер на обычном Linux (unistd.h/axttf/serial/RTC/SHM/порты
    через host-обёртки), что и позволило проверить все 5 сценариев
    (десктоп / Launchpad / Mission Control / fullscreen / reveal)
    отрендеренными кадрами без QEMU.

### Сборка и запуск

    make -C server            # wserver.bin
    make -C apps initrd       # initrd.img (включая wserver + quake)
    make limine-iso           # main.iso (нужны xorriso + limine-tool)

Хост-харнесс (визуальная проверка GUI без ОС):

    gcc -m64 -O1 -DHOST_HARNESS -DAXTTF_HOSTLOAD -Iserver -Ilib \
        server/wserver.c server/wserver_surface.c server/wserver_menu.c \
        server/wserver_ui.c server/wserver_input.c server/wserver_wallpaper.c \
        server/wserver_launch.c server/wserver_lion.c server/wserver_gfx.c \
        server/wserver_axgl.c server/wserver_libc_glue.c \
        tools/lion_harness.c -o lion_harness && ./lion_harness

Харнесс пишет кадры /tmp/lion_shots/*.bmp.
