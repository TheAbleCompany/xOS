# macOS-модель: глобальное меню + «один процесс — много окон»

Дата: 2026-09-05. Ветка: ArtyomX64 (AXShell).

## Что сделано

### 1. Глобальное меню в стиле macOS (kernel/axshell_ui.c)

Строка меню теперь динамическая и отражает **активное приложение**:

    [X]  <ИмяПриложения>   File   Edit   View              часы/батарея

* **Меню приложения** (второй пункт) — имя и пункты берутся из окна в фокусе:
  `About <App>`, `Hide <App>`, `Quit <App>`. Имя рисуется акцентным цветом —
  аналог «жирного» приложения в macOS. Без окон показывается `xOS`.
* Позиции меню пересчитываются каждый кадр по ширине текста
  (`gfx_text_width`), любое имя помещается в бар.
* **File** → `New Window`, `Close Window`:
  * `New Window` отправляет активному приложению событие `AX_EV_NEWWIN`;
  * `Close Window` закрывает только окно в фокусе.
* **View** — прежние пункты (виджеты, обои, акцент).
* **Hide <App>** минимизирует окно в фокусе.
* **Quit <App>** — Cmd+Q: приложению доставляется `AX_EV_QUIT` во все окна.

### 2. Модель «один процесс — много окон»

Ядро (kernel/axshell_surface.c, axshell_internal.h, lib/axipc.h, lib/syscalls.c):

* Новые события `ax_event.type`:
  * `AX_EV_NEWWIN` (5) — «открой ещё одно окно в этом же процессе»;
  * `AX_EV_QUIT` (6) — «закрой все окна и заверши процесс».
* Новые системные вызовы:
  * `172 AX_SYS_WIN_CLOSE` — приложение уничтожает **одно своё** окно
    (`ax_win_close(canvas)`); процесс продолжает работать, пока жив
    хотя бы один его оконный дескриптор;
  * `173 AX_SYS_WIN_FOCUS` — приложение выводит своё окно на передний план
    (`ax_win_focus(canvas)`).
* `reap_closed_windows()` теперь вычищает **все** окна умершей задачи
  (раньше — только помеченные `closing`): крах/exit процесса больше не
  оставляет окон-сирот.
* **PTY стали ленивыми**: окно по умолчанию создаётся без PTY
  (раньше каждое окно занимало слот из пула на 8 и перехватывало
  глобальную клавиатурную PTY). PTY выделяется при первом
  `ax_term_read/term_write` терминального приложения; клавиатурная PTY
  следует за фокусом (`surf_focus`). Многооконные GUI-приложения больше
  не истощают пул PTY.
* Имя пользовательской задачи = имя ELF (было `"app"`), поэтому док и
  меню корректно определяют запущенные приложения.
* Имя приложения для меню берётся из заголовка окна
  (`ax_surface_win.app_name`).

Оболочка:

* **Док** в стиле macOS: клик по иконке уже запущенного приложения
  **фокусирует** его окно (и разворачивает из минимизации) вместо запуска
  второй копии (`app_focus_running()`).

### 3. Notes — мультиоконный редактор (apps/notes.c, переписан)

Демонстрация новой модели: один процесс владеет до 4 окон.

* Каждое окно — независимый документ: свой буфер, имя файла, dirty-флаг,
  Open-промпт и статус-бар.
* Красная кнопка / `File > Close Window` закрывает **одно окно**
  (`ax_win_close`); процесс завершается, когда закрыто последнее.
* `File > New Window` (глобальное меню) открывает ещё одно окно
  **того же процесса**.
* `App menu > Quit Notes` закрывает все окна и завершает процесс.
* Ctrl+S / Ctrl+O / Ctrl+N работают в каждом окне независимо.

### 4. Восстановлены утерянные файлы проекта

В архиве отсутствовали каталоги drivers/, fs/, mm/, boot/ — они
восстановлены из git-пака (.git/objects + индекс). Часть файлов в паке
также отсутствовала и была **реконструирована**:

* `mm/vmm.h` — интерфейс VMM (vmm_space_t, PAGE_*, vmm_new_address_space,
  vmm_map_page/alloc, vmm_switch, vmm_phys_to_virt).
* `fs/initrd.c/.h` — RAM-слой записи: `initrd_ram_file_t` (24 байта,
  {data,len,cap}), ленивая промоция образов в RAM при первой записи,
  запись с «дырами», корректный `initrd_truncate()` для O_TRUNC
  (без старого memset(ptr, 0, 65536), портившего кучу),
  `initrd_create()` для O_CREAT. Заголовок приведён к формату mkinitrd2
  (magic/type/app_type/name[64]/offset/length), `program_type` узла
  заполняется из образа.
* `fs/open.c` — open(): O_CREAT/O_TRUNC, per-task fd (task_alloc_fd),
  фабрика `make_file()`.
* `fs/rw.c` — read/write/close + `get_file()`.
* `fs/exec.c` — exec(): загрузка ELF, `exec_copy_args()` (argv передаётся
  «как есть»; argc=0 → argv[0]=path), stdio консольных детей подключается
  к ctty вызывающей задачи, kernel-side `exit()`.
* `drivers/pci.c/.h` — минимальный PCI-энумератор (для `make -C drivers`).
* `drivers/keyboard_map.h` — добавлены таблицы `keyboard_map_shift` и
  `keyboard_map_caps` (нужны клавиатурному драйверу и axshell).

### 5. Исправлен системный баг strcpy (lib/libc.c)

Старый `strcpy` **не копировал нуль-терминатор**:

    do { *dest++ = *src++; } while (*src != 0);   /* '\0' терялся */

Из-за этого имя файла, созданного во время работы (notes → Ctrl+S),
получало мусор после последнего символа, `finddir/strcmp` его не
находил, и `cat untitled.txt` печатал «cannot open». Теперь:
`while ((*d++ = *src++) != 0);` — терминатор копируется.

### 6. Сборка

* `make` в корне — ядро `main.elf` (все Makefile приведены к табам,
  fs/Makefile дополнен rw.o/open.o/exec.o).
* Приложения: `make notes.bin` в apps/ (gcc -nostdlib -static -pie).
* initrd: `scripts/repack_initrd.py initrd.img initrd_new.img
  notes=apps/notes.bin` — точечная замена notes в готовом образе
  (tcc/lua/libc.a не пересобираются и не теряются).
* ISO: `limine-iso` (xorriso + `limine bios-install`).

## Проверено в QEMU (скриншот-тесты через монитор)

1. Меню показывает активное приложение акцентом (`Notes`, `Files`, `XSH`);
   без окон — `xOS`.
2. `File > New Window` → **второе окно того же процесса Notes**
   (1 × APP_TASK_SPAWNED, 2 × SURF_ALLOC), в статус-баре «New window».
3. Красная кнопка второго окна → `SURF_DESTROY`, **первое окно живо**,
   процесс не завершался.
4. `Notes > Quit Notes` → `APP_QUIT`, окна уничтожены,
   `TASK: exit` у wrapper и user-задач, меню вернулось к `xOS`.
5. Терминал: `echo hi` → `hi` (ленивая PTY + line discipline),
   `cat test.txt` → содержимое (exec + stdio через ctty).
6. Notes: Ctrl+S → «Saved: untitled.txt»; из другого процесса
   `cat untitled.txt` печатает сохранённое (создание файла в initrd +
   чтение работают между процессами).

## Новое API для приложений (lib/libax.h)

    uint32_t *c2 = ax_surface("Notes", w, h);  // второе окно процесса
    ax_win_focus(c2);                          // вывести на передний план
    ax_win_close(c2);                          // закрыть одно окно

События в цикле опроса: `AX_EV_CLOSE` (это окно), `AX_EV_NEWWIN`
(открыть ещё окно), `AX_EV_QUIT` (закрыть всё и выйти).

## Известные ограничения / дальше

* Отрисовка `ax_commit` по-прежнему блитит окно мгновенно, минуя z-order
  (перекрытые окна могут «просвечивать» при постоянной перерисовке
  терминала) — унаследовано от старого движка, к macOS-модели отношения
  не имеет; лечится переносом blit целиком в compose() по z.
* Edit-меню — заглушки (клипборда в ОС пока нет).
* `ls` в терминале по-прежнему молчит (легаси-приложение, читает каталог
  через старый интерфейс) — на файлы, созданные в рантайме, не влияет:
  `cat`/`files` их видят.
