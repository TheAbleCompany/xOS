# Автоопределение ФС: работа на реальном железе

Что изменено и почему. Проверено в QEMU (см. `tests/hw-matrix/`);
на реальном железе НЕ запускалось -- см. «Границы».

## Найденные дефекты исходной версии

| # | Дефект | Эффект на железе |
|---|--------|------------------|
| 1 | GPT-заголовок читался по неверным смещениям (+56/+64/+68 вместо +72/+80/+84) | **ни один GPT-диск не монтировался** (а это любой диск современного ПК) |
| 2 | PCI-скан: шины 0..3, функции 0..1 | AHCI Intel PCH (`00:1f.2`), любые устройства за мостами и на шинах >3 не находились |
| 3 | NVMe не поддерживался | единственный диск ноутбука/ПК после ~2015 невидим |
| 4 | «Текущий диск» ixk_storage оставался последним просканированным | при ≥2 накопителях чтение шло с **не того** диска, а запись-проба писала **на другой диск** |
| 5 | ABAR = BAR5 без маски флагов (биты 3:0) | неверный адрес MMIO при prefetchable-BAR |
| 6 | Нет BIOS/OS handoff, нет ожидания линка/spin-up, нет recovery после ошибок команды | зависания/пропажа дисков на реальных HBA |
| 7 | Сектор диска и «сектор ФС» считались равными 512 | 4Kn-диски и FAT/NTFS с `bytes_per_sector=4096` читались/**писались по неверным адресам** |
| 8 | Нет CRC GPT, нет резервного GPT | мусорные/устаревшие таблицы принимались, повреждённый первичный заголовок = диск пропадал |
| 9 | Детект ФС: ext по одному magic, FAT без валидации BPB, `superfloppy` ломался на загрузочных секторах FAT | ложные срабатывания и пропуски |
| 10 | Запись в ext4 с `metadata_csum` без пересчёта crc32c | после записи Linux видит `Checksum errors` |
| 11 | Нет FLUSH CACHE | потеря данных в кэше диска при отключении питания |

## Что сделано

**Новое**
- `drivers/pcix.[ch]` -- обход всего PCI через мосты (multifunction, secondary-шины),
  BAR (32/64-бит, маска флагов), MMIO (UC), DMA (непрерывные страницы, ниже 4 ГиБ только
  если HBA не S64A), задержки.
- `drivers/nvme.c` -- NVMe (polling): admin + IO очередь, Identify, список активных
  namespace-ов, LBA 512..4096, PRP/PRP-list, Read/Write/Flush.

**Переписано**
- `drivers/ahci.c` -- любое число контроллеров; BOHC handoff; PI==0 fallback; stop/HBA reset;
  POD/SUD, пробуждение из Partial/Slumber, ожидание DET и COMRESET; готовность TFD;
  фильтр SIG (ATAPI/PM/SEMB пропускаются); IDENTIFY с повторами; 4Kn; LBA28/48; recovery
  порта после ошибки; FLUSH CACHE.
- `drivers/blkdev.[ch]` -- PCI-driven: IDE compat **и native** (BAR0..3), AHCI, NVMe;
  `BLKDEV_MAX=16`; эмуляция 512-байтных секторов поверх 1K/2K/4K (с RMW); модель диска;
  lazy-flush (`blkdev_flush`).
- `fs/ix/ix_fs_detect.[ch]` -- `ix_fs_probe()`: строгая валидация FAT/NTFS/ext/exFAT,
  версия ext2/3/4, проверка incompat/ro_compat-фич, опознавание BitLocker, LUKS, swap, XFS,
  Btrfs, F2FS, LVM, md-RAID, ISO9660, HFS+, APFS, ReFS и пустых разделов (не монтируются,
  причина в логе). `ix_fs_detect()` оставлен для совместимости.
- `fs/ix/ix_automount.c` -- GPT (CRC32, резервный заголовок, 4K-секторы, no-automount),
  MBR (проверка правдоподобия, EBR с 64-бит LBA и защитой от петель), superfloppy,
  **выбор диска перед каждой операцией ФС**, sync после записи, `AUTOMOUNT_MAX_DISKS=16`.
- `fs/ix/ix_fs_fat.c`, `ix_fs_ntfs.c` -- пересчёт «сектора ФС» (512..4096) в 512-байтные LBA.

## Изменения поведения (осознанные)

- ext с `metadata_csum`, `needs_recovery`, не-clean state, quota/bigalloc/mmp/casefold/...
  монтируются **только на чтение** (`automount_read_only()`). Прежнее поведение для csum:
  `-DIX_EXT_ALLOW_CSUM_WRITE`.
- ext с inline_data / encrypt / meta_bg / compression / journal_dev не монтируются.
- GPT-разделы с атрибутом «no automount» (Windows recovery и пр.) пропускаются.
- Метка ФС в UI для ext теперь `ext2`/`ext3`/`ext4`.

## Тесты (QEMU; `tests/hw-matrix/`)

MBR/GPT/EBR/superfloppy x IDE / AHCI(`00:1f.2`) / NVMe; 4Kn NVMe (GPT в 4K-секторах,
FAT32 bps=4096, NTFS bps=4096); повреждённый первичный GPT -> резервный; 2 AHCI + NVMe за
root-port на шине 5, три диска с разным содержимым; 11 «чужих» ФС реальными mkfs;
fsck.vfat/e2fsck после записи -- чисто; хост-тест разбора IDENTIFY (4Kn/512e/LBA28/ATAPI).

## Границы (не покрыто)

USB mass storage (флешки), SD/eMMC (SDHCI), Intel RST/VMD-remap NVMe (в RAID-режиме
BIOS NVMe-диск скрыт -- переключить в AHCI), мультисегментные серверные PCI (нужен ACPI MCFG),
ATAPI/оптика, драйверы exFAT/Btrfs/XFS/..., расшифровка BitLocker/LUKS.
SATA 4Kn проверен только на уровне разбора IDENTIFY (QEMU не эмулирует 4Kn на SATA).

# Обновление 2: диагностика на железе без COM-порта, правка AHCI, ext

Поводом стал отчёт: на B450M-HDV и H61MHB диски не определяются, виден лишь пустой `disk0`.
Причину без лога с этих плат назвать нельзя, поэтому добавлена диагностика и исправлено то,
что реально могло ломать инициализацию на настоящих контроллерах.

## Диагностика (читается без serial)
- `debug_putc` дублирует вывод в буфер 64 КиБ (`lib/syscalls.c`, `debug_log_data()`).
- После автомонтирования ядро создаёт в корне initrd файл **`storage.log`**:
  из терминала `cat storage.log`. В нём: полный список PCI-функций (`[PCI] bb:dd.f ven:dev class`),
  мосты и их шины, каждый ATA-канал (`[ATA]`, причина пропуска), каждый порт AHCI
  (`SSTS/SERR/TFD/SIG/CMD`, причина пропуска), NVMe, сырой LBA 0 с таблицей MBR, GPT/CRC,
  результат каждого раздела и `[FS]`-листинг.
- Краткая сводка на экран (`PCI: N fn; AHCI a, NVMe n, IDE i; disks d` + строка на диск).
  При проблеме (нет дисков / дисков больше, чем смонтированных томов) -- пауза 8 с.

## Исправления по реальному железу
- **AHCI: порядок инициализации порта.** Раньше COMRESET выполнялся до включения приёма FIS
  (`PxCMD.FRE`), и ответный D2H-FIS с сигнатурой терялся: порт оставался «занят».
  Теперь: stop -> CLB/FB -> `FRE` -> линк (COMRESET при необходимости) -> готовность TFD -> SIG -> `ST`.
- **COMRESET и при DET=0.** На платах с Fast Boot прошивка не поднимает SATA-линк заранее.
- Ожидание готовности TFD до 10 с (spin-up HDD) + повторный COMRESET при зависании.
- **Задержки по TSC** (калибровка по каналу 2 PIT, ~10 мс) вместо порта 0x80, скорость которого
  отличается у чипсетов в разы. Запасной вариант -- порт 0x80.
- ATA PIO: таймауты BSY/DRQ по времени (~10 с), причины пропуска каждого устройства в лог.
- IDE-контроллер: рядом с BAR-каналами всегда опрашиваются и legacy-порты 1F0/170.
- Лог I/O-ошибок блочного слоя (первые 16).

## ext2/3/4 (чтение)
- Файлы **с дырками (sparse)** читались только до первой дыры -- теперь дыра = нули
  (ошибка чтения индекса отличается от дыры и прерывает чтение).
- Extent длиной 32768 блоков (`ee_len == 0x8000`, так Linux пишет большие файлы) обнулялся
  маской `0x7FFF` -- файлы > 128 МиБ (блок 4 КиБ) читались бы с обрывом. Исправлено;
  unwritten-extent (`ee_len > 32768`) читается как нули.

## Присланные драйверы (iXlinx)
Разобраны и сравнены, **в дерево не внесены** (причины в ответе): это тот же апстрим, из которого
получены наши `ix_fs_*.c` (в `ixstd_fs.h` так и написано); чтение ext/FAT/NTFS на тестовых образах
совпадает с нашим побайтно; блочного слоя (PCI/AHCI/NVMe/IDE) в присланном нет. Найдено:
- `detect_ext` читает feature-флаги по смещениям +96/+100 вместо +92/+96/+100: ext3 определяется как ext2;
- те же дефекты sparse/extent-32768 в `ext_read`;
- `ntfs_write`/`shrink` -- запись в NTFS реальных дисков намеренно не включалась;
- `part_sectors == 0` приводит к отказу монтирования (в нашей версии допускается).

# Обновление 3: чтение файлов и каталогов через VFS

Жалоба: «одни файлы читаются как папки, большинство файлов не читается вообще».
Причины найдены обходом дерева через те же `resolve_path`/`readdir_fs`/`read_fs`, что и в Files
(самотест `-DFS_TREE_SELFTEST`, `automount_selftest()`), и подтверждены на исходных драйверах.

| Симптом | Причина | Исправление |
|---|---|---|
| файл открывается как папка | FAT LFN и NTFS: любой символ >= 128 заменялся на `_`; `Папка` (dir) и `Текст` (файл) оба становились `_____`, поиск находил первую запись -- папку | UTF-16 -> UTF-8 (`ix_utf8.h`, суррогаты), регистронезависимое сравнение по кодпоинтам (ASCII, Latin-1, греч., кириллица); создание LFN кодирует UTF-8 -> UTF-16 (раньше писались байты как символы) |
| после ~64 открытых путей остальные файлы «не существуют» | кэш узлов 64 шт. на том, при переполнении `finddir` возвращал NULL | растущий кэш до 8192 узлов + хеш-таблица, опознание узла без линейного поиска |
| пути длиннее 127 символов | путь хранился в `fs_node_t.name[128]` и обрезался молча (получался другой путь) | полный путь до 512 байт в `am_node_t`, `name` = последний компонент |
| большие файлы «зависают» | `fat_read_at` на каждый кусок заново искал путь и проходил цепочку кластеров с начала; `ntfs` «проматывал» offset чтением по 512 байт с начала; ext заново разбирал путь | кэш поиска + позиции в цепочке (FAT, сброс при любой записи), `ntfs_read_at` с кэшированным дескриптором, кэш path->inode (ext) |
| листинг каталога O(N^2) | каждый `readdir(index)` открывал каталог и читал `index` записей заново (в ext с чтением inode на запись) | курсор каталога (последовательные вызовы продолжают) |
| ext: чтение обрывалось на дыре, extent 32768 блоков = 0 | см. обновление 2 | исправлено |
| NTFS: малые (резидентные) файлы читались всегда с начала | `ntfs_read_resident_data` игнорировал смещение | срез по смещению |
| после дозаписи длина файла не росла | условие `r > length` вместо `offset + r > length` | исправлено |
| `readdir` ext/FAT зависел от общего буфера | продолжение читало мусор, если между вызовами что-то читалось | сектор/блок каталога подгружается в начале каждого вызова |

Результат самотеста на GPT-диске FAT32 + ext2 + NTFS (кириллица, 150 файлов в каталоге, путь 257
символов, файл 3 МиБ): 168/168, 168/168, 157/157 записей, размеры и контрольные суммы совпали с эталоном.

Известные ограничения: NTFS -- нет `$ATTRIBUTE_LIST` и фрагментированного `$MFT`, не более 128
фрагментов (runs) на файл; имя записи > 127 байт UTF-8 обрезается (`struct dirent`).
