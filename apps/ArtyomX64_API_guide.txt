ARTYOMX64 РУКОВОДСТВО ПО ИСПОЛЬЗОВАНИЮ API Версия документа:
предварительная Основано на исходном архиве ArtyomX64(6).zip

====================================================================== 1.
НАЗНАЧЕНИЕ И СОСТОЯНИЕ ДОКУМЕНТА
======================================================================

Это практическое введение в API ArtyomX64 для разработчиков
пользовательских программ. Документ описывает интерфейсы, обнаруженные в
исходниках проекта: lib/libax.h, lib/axport.h, lib/axipc.h,
lib/axquartz.h, lib/axaqua.h, apps/axgl.h, а также описанные в README и
CHANGES-windowserver.md механизмы.

Важно: это не обещание полной POSIX-совместимости и не окончательная
ABI- спецификация. В проекте есть функции libc и совместимые по
назначению интерфейсы, но поддержка отдельных системных вызовов и
семантика ошибок могут отличаться от Linux/BSD. При изменении исходников
номера системных вызовов и структуры сообщений нужно сверять с
актуальными заголовками.

Главный принцип GUI: приложение не управляет экраном напрямую. Оно
создаёт окно через клиентскую библиотеку, рисует в буфер окна и сообщает
WindowServer, когда кадр обновлён. WindowServer работает отдельным
пользовательским процессом wserver и отвечает за композицию окон, ввод,
меню и оболочку.

======================================================================
2. ОСНОВНЫЕ СЛОИ API
======================================================================

1)  Базовые системные вызовы: lib/syscalls.h, lib/syscalls.c,
    lib/unistd.h. Вызов выполняется через программное прерывание int
    0x80. В текущих пользовательских обёртках номер вызова передаётся в
    EAX; аргументы — через регистры, соответствующие обёртке (обычно
    RDI, RSI, RDX, RCX). Не следует переносить номера Linux-системных
    вызовов автоматически: одинаковые номера не гарантируют одинаковую
    реализацию или ABI.

2)  IPC и системные примитивы: lib/axport.h, lib/axipc.h. Порты
    используются для передачи копий сообщений между процессами. Они
    образуют основу общения приложений с WindowServer.

3)  GUI-клиент: lib/libax.h. Создание окна, обработка событий,
    обновление канваса, управление окнами, меню, экраном, временем и
    терминальными сессиями.

4)  2D-графика: lib/libax.h предоставляет базовые операции ax_px,
    ax_fill, ax_rect, ax_text. lib/axquartz.h предоставляет более
    богатые примитивы aq_*. lib/axaqua.h содержит компоненты интерфейса
    и визуальные токены Aqua.

5)  3D: apps/axgl.h содержит AxGL — компактный OpenGL-подобный
    интерфейс. Он использует программный растеризатор и может отправлять
    треугольники в доступный GPU-путь. Это не следует считать полной
    реализацией OpenGL.

======================================================================
3. СОЗДАНИЕ ПРОСТОГО GUI-ПРИЛОЖЕНИЯ
======================================================================

Минимальный пример (C):

    #include "libax.h"

    int main(void)
    {
        uint32_t *canvas = ax_surface("Моё приложение", 480, 320);
        if (!canvas)
            return 1;

        ax_fill(AX_RGB(245, 245, 250));
        ax_text("Привет, ArtyomX64!", 24, 40, AX_RGB(30, 30, 40));
        ax_rect(24, 64, 180, 2, AX_RGB(10, 132, 255));
        ax_commit(canvas);

        for (;;) {
            ax_event ev;
            int rc = ax_poll(canvas, &ev);

            if (rc == 1) {
                if (ev.type == AX_EV_CLOSE)
                    break;

                if (ev.type == AX_EV_RESIZE) {
                    /* После изменения размера перечитайте размеры
                       канваса и перерисуйте содержимое. */
                }
            } else if (rc < 0) {
                break; /* соединение с GUI недоступно */
            }

            ax_yield();
        }

        ax_win_close(canvas);
        return 0;
    }

Примечания: - ax_surface(title, width, height) создаёт окно и возвращает
указатель на 32-битный канвас либо 0 при ошибке. - После ax_surface()
глобальные g_canvas, g_cw и g_ch устанавливаются библиотекой
автоматически. - Цвет хранится в формате 0xAARRGGBB. AX_RGB(r,g,b)
задаёт непрозрачный цвет, AX_ARGB(a,r,g,b) позволяет указать
альфа-канал. - Координаты графических примитивов локальны относительно
канваса окна. - После рисования вызывайте ax_commit(canvas), чтобы
сервер отметил окно изменённым и включил его в композицию. - ax_poll()
не обязан блокироваться: 1 означает событие, 0 — событий нет, -1 —
ошибка/нет соединения. Для кооперативного ожидания можно вызывать
ax_yield(). - В текущем коде сообщения/события буферизуются в
ограниченном кольце; не рассчитывайте на бесконечную очередь событий.

======================================================================
4. ОСНОВНЫЕ ФУНКЦИИ libax.h
======================================================================

Окна: ax_surface(title, w, h) Создать окно. Возвращает указатель
uint32_t* на канвас или 0. ax_poll(canvas, &event) Получить следующее
событие указанного окна. ax_commit(canvas) Сообщить WindowServer, что
содержимое окна изменилось. ax_resize(canvas, w, h) Запросить изменение
размера; возвращает новый указатель канваса либо 0 при неудаче. После
успешного изменения используйте возвращённый указатель и обновите
размеры/содержимое. ax_win_close(canvas) Закрыть одно окно.
ax_win_focus(canvas) Попросить сервер вывести окно на передний план.

Экран и время: ax_screen(&screen) Запросить размеры экрана в структуре
ax_screen_t. ax_time(&time) Запросить календарное время через
WindowServer в структуре ax_time_t.

Меню: ax_menu_set(&definition) Передать серверу описание меню
приложения. Структура сериализуется в wire-формат; не предполагайте, что
указатели на строки передаются серверу напрямую. Смотрите определения
ax_menubar_def_t и ax_menubar_wire_t в lib/axipc.h и lib/libax.h.

Процессы: ax_task_alive(pid) Проверить, существует ли задача с указанным
PID. ax_getpid() Получить PID текущего процесса.

Терминал: ax_term_claim(canvas) Привязать терминал к окну приложения.
ax_term_read(canvas, buf, maxlen) Прочитать данные терминала, связанного
с окном. ax_term_write(canvas, buf, len) Записать данные в терминал,
связанный с окном. ax_term_open(), ax_term_read_id(), ax_term_write_id()
Более низкоуровневые функции работы с tty/PTY.

IPC: ax_port_create(name) Создать именованный порт; NULL/0-имя
используется для анонимного порта. ax_port_lookup(name) Найти порт по
имени. ax_port_send(port, &message) Отправить сообщение.
ax_port_recv(port, &message) Попытаться получить сообщение; при
отсутствии сообщения возвращает значение, отличное от успешного приёма.
ax_yield() Передать управление планировщику.

Возвращаемые значения и точные детали структур следует сверять с
заголовками текущей версии, особенно при обработке ошибок.

======================================================================
5. СОБЫТИЯ ОКОН
======================================================================

В lib/axipc.h определены основные типы событий:

AX_EV_NONE = 0 AX_EV_KEY = 1 AX_EV_MOUSE = 2 AX_EV_CLOSE = 3
AX_EV_RESIZE = 4 AX_EV_NEWWIN = 5 AX_EV_QUIT = 6 AX_EV_MENU = 7
AX_EV_RAWKEY = 8

Структура ax_event включает тип события, клавишу, координаты мыши,
кнопки и параметры размера окна. Точный состав полей нужно брать из
axipc.h.

Пример обработки: if (ev.type == AX_EV_MOUSE) { /* ev.mx, ev.my —
координаты события мыши / } else if (ev.type == AX_EV_KEY) { / ev.key —
код клавиши/действия / } else if (ev.type == AX_EV_CLOSE) { / Завершить
приложение или закрыть это окно */ }

В заголовке также есть специальные значения клавиш, в том числе
AX_KEY_BACKSPACE, AX_KEY_ENTER и коды для некоторых сочетаний Ctrl.
Используйте символические константы вместо числовых значений.

======================================================================
6. РИСОВАНИЕ В 2D
======================================================================

Базовые примитивы libax.h: ax_px(x, y, color) — нарисовать пиксель.
ax_fill(color) — заполнить весь канвас. ax_rect(x, y, w, h, color) —
заполнить прямоугольник. ax_text(text, x, y, color) — вывести текст.
ax_text_width(text) — измерить ширину строки. ax_canvas_dims(w, h) —
задать размеры для низкоуровневого рисования вручную.

Расширенные примитивы lib/axquartz.h: aq_px(), aq_px_alpha(),
aq_get_px() aq_clear(), aq_fill(), aq_fill_alpha() aq_hline(),
aq_vline(), aq_rect_outline(), aq_line() aq_rounded_fill(),
aq_rounded_outline() aq_vgradient(), aq_hgradient() aq_circle_aa(),
aq_soft_shadow(), aq_blit() aq_text(), aq_text_bold(), aq_text_scaled()

AquaKit (lib/axaqua.h) предоставляет готовые элементы визуального
оформления: фон окна, панели инструментов, статусные панели, кнопки,
поля и цветовые токены. Для использования компонентов подключите
axaqua.h и вызывайте функции aq_/aqaqua-компонентов, которые реально
определены в заголовке. Этот слой ориентирован на единый Aqua-подобный
стиль приложений.

Общий порядок рисования: 1. Создать окно через ax_surface(). 2.
Нарисовать фон и содержимое. 3. Вызвать ax_commit(). 4. В цикле получать
события через ax_poll(). 5. При изменении данных перерисовать нужные
области и снова вызвать ax_commit().

7. МЕНЮ ПРИЛОЖЕНИЯ
======================================================================

Для меню используйте ax_menu_set() и определения из lib/axipc.h/libax.h.
Лимиты, указанные в заголовке: AX_APP_MENUS_MAX = 4 AX_MENU_ITEMS_MAX =
6 AX_MENU_TITLE_MAX = 16 AX_MENU_ITEM_MAX = 24

Есть стандартные действия приложения: AX_APPITEM_ABOUT = 0
AX_APPITEM_HIDE = 1 AX_APPITEM_QUIT = 2

Ограничения на длину заголовков/пунктов существуют из-за фиксированного
wire-формата сообщений. Передавайте корректно сформированные структуры и
не превышайте указанные лимиты.

======================================================================
8. ТЕРМИНАЛ И ПСЕВДОТЕРМИНАЛ
======================================================================

WindowServer использует терминальные функции ядра для подключения окон
терминала к PTY. В документации проекта указана следующая модель: -
TERM_OPEN создаёт терминальную сессию; - терминальная сторона процесса
наследуется дочерними процессами через стандартные дескрипторы; -
TERM_READ/TERM_WRITE используются для обмена данными; - TERM_FOCUS
направляет ввод клавиатуры к активному терминалу.

Для GUI-приложения типичный порядок: 1. Создать окно. 2. Вызвать
ax_term_claim(canvas). 3. Периодически читать вывод через
ax_term_read(). 4. Передавать ввод через ax_term_write().

Точный формат терминальных событий и поведения ввода зависит от текущей
реализации tty/PTY. Для обычного текстового приложения сначала проверьте
стандартные stdin/stdout и доступные функции libc.

======================================================================
9. IPC: ПОРТЫ И СООБЩЕНИЯ
======================================================================

Основные номера системных вызовов, описанные в текущей версии проекта:
178 PORT_CREATE(name) 179 PORT_LOOKUP(name) 180 PORT_SEND(port, msg) 181
PORT_RECV(port, msg) 182 GETPID() 183 SHM_ALLOC(size) 184 SHM_FREE(ptr)
185 TERM_OPEN() 186 TERM_READ(id, buffer, maxlen) 187 TERM_WRITE(id,
buffer, len) 188 TERM_FOCUS(id) 189 FB_INFO(out) 190 INPUT_MOUSE(out)
191 INPUT_KEY(out) 192 PROC_NAME(pid, …) 193 GPU_SUBMIT_RT(…) 195
TERM_RELEASE(id)

Номера 178–195 относятся к описанным в проекте IPC/системным примитивам,
но не все функции обязаны быть доступны как публичные функции libc. Для
приложений предпочтительнее использовать готовые обёртки и заголовки.

Типы сообщений WindowServer описаны в lib/axport.h. Среди них:
MSG_REQ_SURFACE / MSG_REPLY_SURFACE MSG_REQ_COMMIT MSG_REQ_WIN_CLOSE
MSG_REQ_WIN_FOCUS MSG_REQ_RESIZE / MSG_REPLY_RESIZE MSG_REQ_MENU_SET
MSG_REQ_SCREEN / MSG_REPLY_SCREEN MSG_REQ_TIME / MSG_REPLY_TIME
MSG_REQ_TERM_ATTACH MSG_REQ_GL_BEGIN / MSG_REQ_GL_TRI / MSG_REQ_GL_END
MSG_EVENT

Обычно клиенту не нужно формировать GUI-сообщения вручную: libax.h
делает это за него. Низкоуровневый IPC нужен для собственных служб и
расширенных сценариев.

Ограничения, описанные в документации текущего исходного состояния: -
очередь порта ограничена; - отправка может завершиться неудачно или
потерять сообщение при переполнении; - порты не передаются между
процессами автоматически; - сообщения копируются ядром; - клиентский API
ожидает сервер с именем “wserver”.

======================================================================
10. AxGL: 3D-ГРАФИКА
======================================================================

В apps/axgl.h содержится AxGL — небольшой OpenGL-подобный API. Он
включает операции инициализации контекста, viewport, матриц,
перспективы, переносов, масштабирования, вращения, цвета,
begin/vertex/end и очистки кадра.

В исходниках присутствуют функции вида: axgl_init(canvas, w, h)
axgl_viewport(w, h) axgl_matrix_mode(mode) axgl_load_identity()
axgl_perspective(fovy_deg, aspect, near, far) axgl_translatef(x, y, z)
axgl_scalef(x, y, z) axgl_rotatef(angle_deg, x, y, z) axgl_color3f(r, g,
b) axgl_color4f(r, g, b, a) axgl_begin(primitive) axgl_vertex3f(x, y, z)
axgl_clear(color) axgl_end() axgl_backend() axgl_set_render_mode(mode)

Перед использованием проверьте точные сигнатуры и допустимые значения в
apps/axgl.h. API является проектным и не гарантирует совместимость со
всеми функциями OpenGL. Графический путь может быть программным;
доступность GPU зависит от драйвера и платформы.

======================================================================
11. ФАЙЛЫ, ПРОЦЕССЫ И C
======================================================================

В проекте есть пользовательские ELF-программы, libc и средства
портирования. Обычные программы используют C и функции стандартной
библиотеки, если нужные функции реализованы в mini-libc/libc для этой
сборки.

Пути файлов, доступные приложению, определяются файловой системой
ArtyomX64 и содержимым initrd. Не следует предполагать, что все пути,
устройства, права, сигналы и системные вызовы Linux/BSD уже реализованы.

Пример простого консольного приложения:

    #include <stdio.h>

    int main(void)
    {
        puts("Hello from ArtyomX64");
        return 0;
    }

Сборка приложений и включение их в initrd зависят от Makefile проекта. В
текущем дереве есть каталог apps и документация по портированию,
например apps/README-PORT.md и apps/README-TCC-PORT.md. Используйте
команды сборки, указанные в актуальном README проекта; не копируйте
Linux-команду линковки без проверки startup-файла, ABI, заголовков и
libc ArtyomX64.

======================================================================
12. ПРАКТИЧЕСКИЕ ПРАВИЛА
======================================================================

-   Для GUI используйте libax.h, а не прямой доступ к framebuffer.
-   После рисования вызывайте ax_commit().
-   Проверяйте результат ax_surface() и других функций, которые могут
    вернуть нулевой указатель или код ошибки.
-   При закрытии окна корректно обработайте AX_EV_CLOSE и вызовите
    ax_win_close().
-   После resize используйте новый указатель канваса, возвращённый
    ax_resize().
-   Не предполагайте, что ax_poll() блокируется.
-   Не используйте Linux syscall numbers напрямую без проверки
    реализации ядра.
-   Не считайте наличие BSD/Unix-подобных номеров системных вызовов
    полной бинарной совместимостью с конкретным Unix.
-   Не используйте неподтверждённые структуры сообщений: сверяйте
    ax_event, ax_time_t, ax_screen_t, ax_msg_t и меню с заголовками.
-   Для новых API сначала проверьте заголовок, реализацию в ядре/сервере
    и пример работающего приложения.

13. ФАЙЛЫ, КОТОРЫЕ СЛУЖАТ СПРАВОЧНИКОМ
======================================================================

lib/libax.h — основной клиентский GUI API и обёртки. lib/axport.h —
формат IPC-сообщений WindowServer. lib/axipc.h — события, меню и
структуры данных. lib/axquartz.h — 2D-примитивы. lib/axaqua.h — AquaKit:
стили и виджеты. apps/axgl.h — AxGL. lib/syscalls.h — макросы и обёртки
системных вызовов. lib/unistd.h — часть POSIX-подобных объявлений
проекта. lib/syscalls.c — реализация системных вызовов. kernel/ipc.c —
IPC/SHM/TTY и связанные системные примитивы. server/wserver*.c —
пользовательский WindowServer. apps/README-PORT.md
apps/README-TCC-PORT.md — материалы по портированию приложений.
